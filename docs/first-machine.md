# 新电脑快速安装与同花顺适配

本项目复用的是执行流程和适配器，不是一个覆盖所有券商的官方交易API。同样叫“同花顺交易端”，不同券商、经典/新版交易页、控件结构、字体和显示缩放仍可能不同。常见布局可以通过本机配置适配；结构不同的客户端可能需要修改适配器。**生成配置、读取成功、券商受理、真实成交是四个不同结果。**

这份指南归纳了2026-10-16一次新电脑部署中实际发现的问题，相关通用修复已进入0.3.0，不应让每个使用者重复修改代码。

## 最短流程

1. 从GitHub Releases下载项目分享包，解压到可写目录。首次准备Windows 10/11及Python 3.11+，保留pip、venv和Tcl/Tk组件。安装脚本优先选择已安装的Python 3.12，否则使用系统Python；本次现场验证为64位Python 3.13.5。
2. 双击 `Setup.cmd`。它显示四个阶段：检查Python、准备独立环境、安装依赖、用空白图片检查OCR。首次需要下载依赖或模型，耗时取决于网络；**这段时间与交易客户端适配耗时不同**。此步骤不会控制交易端或下单。
3. 双击 `Check-Environment.cmd`。先解决Python/Tk/依赖缺失；尚未生成本机配置时出现提示是正常的。
4. 自己打开并登录同花顺**交易端**，保留一个目标交易窗口。先处理登录、验证码、交易确认或错误提示；程序不代填密码或验证码。
5. 双击 `Configure-Client.cmd`。工具只读发现交易窗口和程序路径，询问券商及账户身份片段，写入 `config/ths.local.json`。常见账户下拉框可提供默认身份片段和截图区域。已有配置时拒绝覆盖。窗口不唯一、身份区域无法可靠定位时会停止并说明需要人工配置。
6. 双击 `Start-Test-Console.cmd`。默认模拟模式；输入自己的代码、数量、限价即可测试模型式指令，不需要预建证券名单。切换实盘后先运行“客户端适配检查”，逐项核对资金、持仓、委托；随后单独刷新盘口核对五档。
7. 只读结果一致后，由使用者自行安排真实委托验收。测试台和HTTP共用执行路径；模型传入明确代码、方向、数量、限价和信号编号，执行端不选股、不追价、不自动反向交易。

配置向导是起点，不是“交易已验收”的证明。它不会切换页面、填单、确认弹窗、买卖或撤单；配置完成后仍需第6步。

为减少依赖漂移，Python 3.13安装会使用 `constraints/windows-py313-tested.txt` 中的本次运行组合；这份清单不含本地路径或项目可编辑安装地址，不能当成所有Python版本的通用锁文件。其他Python版本按项目兼容范围解析依赖。安装只选择二进制wheel，不在用户电脑上耗时编译；提示没有匹配版本时，先核对Windows、Python版本和位数，再查看错误，不必盲目安装编译工具。

## 哪些东西通用，哪些需要本机核对

| 层次 | 当前可以复用 | 本机需要核对 |
| --- | --- | --- |
| 模型协议与账本 | 信号格式、原编号去重、回执、SQLite、HTTP | 账户逻辑别名、数据根目录；重试不换编号 |
| Windows环境 | 安装脚本、环境诊断、OCR组件 | Python/Tk、安装权限、网络及依赖是否正常 |
| 交易主窗口 | 唯一窗口与实际进程路径核对 | 本机交易exe、标题正则、券商/账户身份；行情主程序不是交易exe |
| 新旧交易表单 | 显式市场选择框、按代码自动识别、无重填按钮清空 | 当前表单是否属于支持结构，代码/名称/价格/数量完整回读 |
| 资金、持仓、委托 | 原生定位、表格线与OCR、滚动合并 | 页面路径、控件ID、列是否显示完整、全部滚动范围 |
| 盘口 | 按DPI定位、局部截图、五档解析 | 当前布局、报价区域宽度、价格/数量/显示时间 |
| 券商柜台 | 提交一次、记录真实结果、不确定结果不补单 | 交易权限、申报规则、时段、夜市/低延时通道能力 |

不能把自己的 `ths.local.json` 直接当作通用配置发给别人；它包含自己的路径和账户身份。分享包仅提供占位模板，各自在自己的电脑生成。

## 命令行诊断

从项目根目录执行。普通环境报告不输出账户片段、窗口标题、完整程序路径、令牌或持仓：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m easytrade.doctor --json
```

仅检查模拟环境，可使用 `--mode paper`。尚未安装项目时，也可运行标准库引导脚本：

```powershell
python -X utf8 tools/check_environment.py --mode paper
```

以下操作会读取本机窗口信息，输出含私密路径/窗口身份，**不要原样公开**：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m easytrade.doctor --discover
```

多个交易窗口时，先依据发现结果选择目标，向导不会猜测：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m easytrade.doctor --init-config --window-id <发现结果中的window_id>
```

没有自动账户区域、标题不含身份或使用其他窗口布局时，复制 `config/ths.example.json` 为 `config/ths.local.json`，按[本机配置表](quickstart.md#本机实盘配置)及[窗口适配流程](client-adaptation.md)人工校准。保留券商和账户两种身份要求；不能用宽泛标题、空身份片段来绕过核对。

只读验收命令会切换资金/持仓和当日委托页，不买卖、不撤单、不确认任何弹窗：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m easytrade.doctor --check-client
```

完整报告存入本机 `runtime/client-check-live.json`，含账户数据，不能直接发到公开Issue。命令成功只表示读取检查返回成功，仍须人工对照数据。

提前检查OCR模型可以单独运行；只处理空白图片，不截取桌面：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m easytrade.doctor --warm-ocr
```

自动安装时可用 `Setup.cmd --no-pause`；已有离线模型或暂时不检查OCR时可加 `--skip-ocr-warmup`。预热检查能提前暴露模型/运行库问题，并不代表以后每个新进程都没有首次加载开销。

## 本次耗时的原因与已经修复的部分

| 现场现象 | 原因 | 当前处理 |
| --- | --- | --- |
| 首次安装较长 | 下载pywin32、OCR、ONNX、OpenCV等；首次加载模型 | 安装分阶段显示，独立环境复用，安装时检查OCR |
| 只能选择两个样例证券 | 旧测试台把配置名单作为输入限制 | 代码、数量、限价直接输入，取消逐只证券配置及内置名单 |
| 只有3条持仓却读取20至25秒，左侧菜单反复滚动 | 原生封装返回了间接后代控件，误把菜单滚动条当成持仓分页 | 按直接父控件核对滚动条归属，避免反复识别同一表格 |
| 找不到市场下拉框或重填按钮 | 新版客户端自动识别代码且没有旧版按钮 | 区分新旧结构；新版从客户端取名称，按字段清空并回读 |
| 账户名称/报价名称匹配失败 | 持仓简称与实际交易页全称不同 | 交易名称从当前客户端原生控件读取，绑定本次准备 |
| 盘口读不到或区域错位 | 新版布局和144 DPI下报价区域宽度不同 | 按DPI定位并局部截图，缓存仍可见的图表句柄 |
| 明明文字可见却报跨列 | 列太窄或OCR检测框扩张过大 | 先展开真实列宽；必要时调OCR缩放和检测框参数，不放宽完整编号/置信度要求 |
| 收盘盘口时钟停止导致本地拒绝 | 把时段或行情显示时间当成统一提交门槛 | 日历时段不拦截；新读取的有效收盘盘口可作限价，记录本次读取时间 |
| 弹出“低延时98客户不支持夜市”，错误码-150906115 | 该券商通道明确拒绝夜市委托 | 记录已拒绝及原错误；不能伪造成受理、待成交或成交 |

这些修复针对已观察的行为，不能推导所有同花顺版本都已实盘验证。当前现场验证包括新版交易端的资金/持仓、委托、五档、两种代码的买入/卖出准备及清空；实际收盘测试收到的是券商拒单。其他客户端、市场和交易规则仍需各自验收。

## 读数据慢时，按层排查

1. **先区分首次加载与后续读取。** 本次少量热采样：盘口约1.1至1.7秒，切换证券读盘口约2.8秒，字段准备/回读约1.7至2.0秒，账户约2.3秒，委托约2.6秒；一次HTTP首次盘口读取约4.4秒。这些不是整笔成交延迟，也不承诺其他机器达到相同数字。
2. **观察究竟滚动哪里。** 多页持仓正常会滚动表格；左侧菜单持续滚动不应被当成持仓完整性核对。检查版本是否已更新，不要通过跳过完整性检查加速。
3. **查看原生读取耗时。** 本机 `runtime/console-actions.jsonl` 中的 `native_read_timing` 区分窗口绑定、身份OCR、表格OCR和截图。少量一屏持仓通常只需一次表格OCR，多页数据才应有多次；不要机械要求所有账户都只有一次。
4. **文字截断先修列宽。** 证券代码、数量、价格小数点、状态和完整委托号必须可见。放大OCR不能恢复已经被客户端截掉的字符。未知价格显示“—”不等于0。
5. **参数从小处改。** `ocr_scale_by_role`支持1/2/3倍；当前字体清晰可先用1倍，字小再试2倍。文字未截断但检测框扩张过界时可试 `ocr_unclip_ratio: 1.2`，调后重新逐项核对。盘口默认2倍，`quote_panel_width`可覆盖实际像素宽度。
6. **区分输入与查询开销。** 默认 `editor_input_mode: auto`先尝试控件赋值再回退数字键。确认此客户端忽略赋值、数字键正常时，可改为 `keys`减少等待。明确限价默认不额外读账户和盘口；仅在需要时启用 `pretrade_account: true`。
7. **把成交等待单独看待。** 准备成功、已点击提交、已受理和已成交不同；待成交查询、网络/柜台等待不能算作一次截图OCR。不能为了快就跳过字段核对或把成功提示当成成交。

## 本机需要保持的条件

- 保持桌面解锁，客户端与执行端处于相同Windows权限级别；按客户端要求手动处理权限，不需要为项目关闭系统安全设置。
- 读取和准备期间不要切换前台或干预键鼠；前台变化会停止当前操作。不要为了避免停止而允许后台盲输。
- 不要求所有电脑固定相同分辨率。保持**本机已核对的窗口大小、列宽和缩放**；改变DPI、跨不同缩放显示器移动、更新客户端后重新检查。
- 同一客户端由一个工作流操作。测试台与HTTP共享账户锁；不能通过另一个根目录/锁文件绕过串行控制。
- 明确数量和限价按模型指令传递，券商校验实际单位、权限及可卖数量。不要把所有证券都假定为100份，也不要把持仓市价自动改成委托价。
- 收盘能读数据不代表券商支持夜市。明确失败按实际回执记录；不确定结果保留原信号编号核对，不换编号补发。

## 更新、分享与问题反馈

更新前停止执行端正在进行的操作，备份本机配置和完整 `runtime/`，保留原账本。不要为了“重新安装干净”直接删除实盘账本，或在新目录另建账本后重新发送旧信号。仅更新公开源码/分享包文件，原配置、令牌和账本不随版本覆盖。

分享给别人用GitHub Releases的项目zip，或仓库源码。`tools/build_share.py`按公开白名单打包，附逐文件SHA-256及整个zip校验值；不会包含 `.venv`、本机配置、令牌、截图、日志或账本。别人需要在自己的电脑安装依赖、生成自己的配置。

公开反馈可以包含：项目版本/构建号、Python版本/位数、Windows版本、显示缩放、客户端版本及新旧布局、出错的步骤、已脱敏的错误码、冷热耗时。默认 `doctor --json`环境报告不含账户内容。

不要公开 `runtime/`、`ths.local.json`、API令牌、账户标题/尾号、原始委托号、持仓与资金截图。`--discover`输出和只读验收完整报告属于本机私密诊断；需要截图时先脱敏。

## 后续仍值得投入的工作

当前已提供环境检查、窗口发现、配置向导、只读验收和源码分享包。以下属于后续方向，**并非本版本已具备**：

- 收集更多券商/客户端版本的匿名控件结构与脱敏测试样本，维护明确兼容矩阵和不兼容原因。
- 对OCR预处理参数提供有数据行的候选对比，并保留人工核对，避免自动选出“看起来能解析”的错误方案。
- 给经过验证的Python/依赖组合提供独立安装包或离线依赖缓存；本版本仍需要本机Python。
- 在可控测试账户中验证实际受理、部分成交、撤单、跨日及异常恢复；CI和模拟回执不能替代这些实盘验收。
