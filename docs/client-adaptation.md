# 新电脑与窗口适配流程

OCR取决于客户端实际显示的内容。缩小窗口、改变列宽、横向滚动或更换显示缩放后，价格可能被截断、隐藏，网格和文字大小也会变化。执行端按原生控件和当前表格线定位，仍需要在每台电脑核对实际布局。

## 首次使用

1. 用户打开并登录交易客户端，按 quickstart 填好本机身份与控件配置。
2. 把交易窗口调整到日常使用的大小；可最大化，也可用足够宽的普通窗口。展开持仓列，使证券代码、名称、总持仓、可卖数量、市价、市值完整可见，横向滚动回关键列可见的位置。委托表展开完整委托编号、方向、委托数量/价格、成交数量、成交均价和状态。
3. 测试台切换实盘，点击“客户端适配检查”。它依次读取账户持仓和当日委托，切换查询页，不发送买卖、撤单或继续确认。等待结束期间不切前台、不调整窗口。
4. 查看“首次适配检查”页。窗口大小、表格相对范围和DPI是诊断信息；“已读取”表示解析成功，**不表示人工验收通过**。“需调整/读取失败”按提示处理再检查。检查报告存放在本机 `runtime/client-check-live.json`，含账户信息，分享前须脱敏。
5. 对照客户端资金、所有证券代码、总量、可卖数量、价格小数点与市值；委托核对完整编号、方向、数量、价格与状态。没有持仓/委托时只能验证空表读取，不能确认实际数据行的准确性。
6. 选择实际要交易的证券，单独刷新客户端五档并人工对照。账户检查不会自动覆盖交易草稿或准备行情。核对一致后保持当前客户端大小、列宽和系统缩放，再由使用者自行决定小单验证。

## 日常窗口规则

运行期间保持已经核对的**客户端大小、列宽与显示缩放**，尤其不要在一次读取/提交中途拖拽调整。执行端连接会保留正常或最大化状态；最小化时由获取焦点流程恢复。

同一显示器上单纯移动窗口通常不改变表格相对布局。调整窗口大小、隐藏/重排列、改变缩放或分辨率、移到DPI不同的显示器、升级交易客户端后，重新做上述检查。无需强制所有人采用某个固定分辨率，实际可见列与本机核对结果才是依据。

## 市价显示“—”时

- 检查市价/市值列是否完整露出，拖宽列或放大交易窗口，等数据稳定后重新读取。
- 查看账户页“显示提示”。缺表头、空值、低置信、跨列和明显的“市价×总持仓与市值不一致”都会省略相应字段，避免显示看似正常的错误数字。
- 资金和可可靠识别的数量仍会显示；代码或数量不可靠会让本次读取失败，旧数据会明确标注为上次快照。价格缺失不是零，不要用旧价格补齐。
- 若文字仍偏小，可在 `ths_profile` 添加 `"ocr_scale_by_role": {"positions": 2, "orders": 2, "trades": 2}`，重启再检查。支持1/2/3倍，这是OCR预处理缩放，不修改系统DPI；更大缩放可能增加耗时，不能修复已经被客户端截断的文字。
- 身份标题区域不合适时校准 `caption_identity_box`；客户端版本/页面树/控件不同则调整配置或适配器。报价区域还可能需校准 `quote_panel_width`。保持身份核对要求。

数值一致性和置信度只是辅助检查，不能保证捕获每一种OCR错误。持仓市价仅用于展示，不会自动变成买卖委托价格。不同券商/字体/显示缩放的实景准确性仍需要每台机器验收。
