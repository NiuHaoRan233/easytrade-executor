# 实现、数据路径与适配范围

## 执行流程

测试台和 HTTP 共用 UserSession：验证信号 → 账户锁 → 原编号检查 → 可选的账户查询 → 准备原生字段 → 回读核对 → 一次提交 → 回执 → SQLite。模拟用 PaperAdapter 本地账本，实盘用 ThsUserAdapter。

先持久化提交意图，再操作客户端；中断记录恢复为 UNKNOWN，不自动补发。历史待成交不限制新指令；原编号去重、客户端串行和身份检查继续生效。每个新编号都是新的交易意图。

统一实盘入口直接接受代码、方向、正整数数量和明确限价，不要求预配置证券名单、名称或交易规则。名称由客户端识别，提交前与本次准备记录绑定核对；实际交易单位、价格单位、T+1、费用、涨跌停与可卖数量由券商约束。不含选股、仓位算法、止盈止损或自动往返。

## 行情两条路径

默认 `ths_client`，读交易控件右侧最新价、涨幅、五档；核对代码和客户端证券名称，旧版控件还显式选择市场。切换证券时保留已有数量草稿；允许替换客户端自动带出的价格。时间表示客户端显示时间，不能据此推导交易所到本机的真实延迟。

`tencent_web` 保留为手动选择的只读网络渠道。两者不自动故障切换；无效盘口不使用最新成交价或旧价替代，用户可另行明确手填限价。

## 资金持仓与委托

用原生控件定位、切页与读写字段，虚拟表格主要用本地 OCR。可识别滚动条时合并各页并核对底部；不明滚动实现返回可见行和不完整标记。低置信必需字段、缺表头、身份不符与现场变化会拒绝读取，不能解释成空账户。

委托用完整编号并核对账户、证券、方向、数量和价格，不按相似时间猜测。券商表独立展示，包括非本项目创建的订单。

连接验证实际 exe、唯一可见窗口和 PID，操作核对账户标题与前台。标题每次取新像素，相同摘要复用 OCR，变化则重识别；GDI 区域截图与会话复用 OCR 减少开销。

## 性能与验证边界

构建20261016.14的本机热采样：同代码盘口约1.4至1.7秒，切换代码并读五档约2.8秒，买入/卖出字段准备及回读约1.7至2.0秒；账户查询约2.3秒。明确限价默认不额外读账户或盘口。首次OCR初始化、证券切换和回执等待另计，这些数值不是整笔成交延迟或其他电脑的承诺。

少量截图曾与复制表格逐字段对照，但不足以给出长期准确率，不能宣称 100%。其他券商、DPI、隐藏列、多页与字体需各自验收，模型须检查时间与完整性。

连接时保留用户正常/最大化状态，由焦点方法按需恢复最小化。表格读取核对截图前后的窗口大小、表格相对范围和DPI，变化时丢弃该次解析并重读；分页间变化拒绝整次读取。OCR文字框须在检测到的单元格边界内；市价/市值属于显示字段，不可靠时省略并返回警告，关键代码/数量仍严格拒绝。市价×持仓与市值按显示小数精度允许舍入误差，明显不一致时省略两者；这是辅助排错，无法发现所有高置信错误。不会反算替换价格，也不会把持仓市价作为委托限价。

测试台提供本机只读适配检查，结果写入私有运行目录，读取成功仍要求人工核对。合成网格测试覆盖列换序、1/2/3倍缩放、裁切、跨列、低置信和小数点丢失；它们不等于所有真实DPI/客户端组合的实测。

离线测试覆盖幂等、参数冲突、预算与规则、未知结果不补单、未配置代码/明确数量与价格传递、身份/字段契约、回执匹配、串行锁和模拟HTTP；GUI冒烟从空证券名单输入模型式指令，覆盖独立买卖及数据显示。本机新版无市场下拉框/重填按钮的交易页已验证盘口、不同代码的买入/卖出准备及清空；真实提交/确认/成交回执仍需现场验收。

本次整理没有代用户执行真实买卖、撤单或继续确认；通用版不能视为所有券商和证券的实盘验收。每位使用者先在自己的客户端只读核对，再自行决定小单验证。

## 分享边界

`tools/build_share.py` 指定公开文件清单，Git 和压缩包使用同一清单。运行目录、身份配置、凭据、截图、数据库和历史调试材料留在本机。安装包仅含 Python 模块；配置和脚本随源码/分享包提供，运行时 `--root` 指向数据目录。
